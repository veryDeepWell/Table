# За столом

Каталог настольных игр на русском языке: го, шахматы, русские шашки, короткие нарды, сёги, «Точки», «4 в ряд» и маджонг. У всех игр есть сетевой режим и правила с примерами.

## Запуск

Нужен Node.js 22+.

```sh
npm run dev
npm test
npm run build
```

Локальный адрес: http://127.0.0.1:5173. Сборка в `dist/`.

## Сервер комнат

Игроки открывают GitHub Pages. В разделе **Играть по сети** можно создать комнату с именем и паролем, выбрать сторону или случайную рассадку, а затем сообщить друзьям имя комнаты и пароль. Партия начнётся, когда все места заняты.

### Настройка владельцем проекта

В каталоге проекта в PowerShell:

```powershell
npx.cmd wrangler login
npx.cmd wrangler deploy --config cloudflare/wrangler.jsonc
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
npx.cmd wrangler secret put HOST_KEY --config cloudflare/wrangler.jsonc
```

При первом развёртывании Cloudflare может попросить выбрать адрес аккаунта `workers.dev`. На запрос `secret put` вставьте ключ из третьей команды. Храните ключ отдельно и передавайте только тем, кто сможет запускать сервер.

В репозитории GitHub откройте **Settings → Secrets and variables → Actions → Variables**. Создайте переменную `TABLE_REGISTRY_URL` с HTTPS-адресом Worker из вывода `deploy`, без пути `/host`. Опубликуйте изменения и запустите workflow **Deploy GitHub Pages**. Для проверки откройте `/host` на адресе Worker. Пока сервер выключен, ответ будет `{"origin":null}`.

### Запуск на любом компьютере

Установите Python 3, Node.js 22+ и cloudflared. На сайте откройте **Как играть по сети → Скачать сервер комнат**, затем запустите скачанный файл.

```powershell
python za-stolom-server.py
```

При первом успешном запуске файл сохранит введённый ключ на этом ПК. Для замены ключа запустите с `--setup`. Пока окно открыто, файл поддерживает туннель и регистрацию сервера. На сайте в шапке появится «Сервер онлайн». Один сервер обслуживает все комнаты. При смене компьютера сначала остановите предыдущий сервер. Аварийная остановка освобождает регистрацию через 45 секунд.

Для проверки из исходников можно запустить `python host_rooms.py`. В этом случае перед первым запуском также введите HTTPS-адрес Worker. Локальная разработка через `npm.cmd run dev` использует локальный сервер напрямую.

Комнаты хранятся в памяти сервера и закрываются при его остановке или после 30 минут без запросов игроков. Перезагрузка страницы в той же вкладке сохраняет место. Во время партии выход засчитывает поражение, а при потере связи у игрока есть 20 секунд, чтобы вернуться.

## GitHub Pages

В настройках репозитория выберите **Pages → Source → GitHub Actions**. После отправки в `main` workflow `.github/workflows/pages.yml` проверит движок, соберёт сайт и опубликует Pages. Если Pages публикует корень ветки напрямую, запустите `npm.cmd run build -- --branch-pages` и добавьте обновлённый `za-stolom-server.py` в коммит. В таком режиме адрес Worker берётся из `src/online/registry-config.js`. Все пути относительные, маршруты используют hash, поэтому сайт работает в подпапке репозитория.

## Архитектура

- `src/app.js` — общая оболочка, каталог и маршрутизация.
- `src/data/games.js` — реестр игр и ленивые загрузчики модулей.
- `src/games/<id>/engine.js` — чистые функции игровой логики, без DOM.
- `src/games/<id>/view.js` — интерфейс и правила игры.
- `src/online/` — запуск и подключение к комнатам, профиль и чат.
- `server/match.mjs` — общий протокол комнаты, `server/match-games.mjs` — адаптеры игровых движков.
- `src/games/table-view.js` — общая оболочка для шахмат, шашек, нард и сёги с подсветкой ходов, отменой действий и сохранением.
- `src/style.css` — адаптивное оформление и общие компоненты.
- `tests/` — проверки игровых правил средствами Node.js.

Для новой игры добавьте каталог `src/games/<id>/`, экспортируйте `render(root)` из модуля интерфейса и зарегистрируйте игру в `games.js`. Карточки и поиск строятся из реестра. Движки не зависят от интерфейса и хранилища.

## Правила и ограничения

В го используются китайский подсчёт площади, коми 7,5, запрет самоубийства и позиционное суперко. Два паса завершают партию. Мёртвые группы автоматически не определяются: спорные позиции нужно доиграть через «Продолжить игру». Счёт берётся по текущей доске.

Правила сверены с материалами [British Go Association](https://www.britgo.org/intro/intro2.html) и [сравнением систем правил](https://www.britgo.org/rules/compare.html). Google Fonts необязательны: при отсутствии сети используется системный шрифт. Позиция хранится только в localStorage браузера.
