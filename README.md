# За столом

Каталог настольных игр на русском языке: го, шахматы, русские шашки, короткие нарды, сёги и онлайн-маджонг для четверых. Первые пять игр работают локально, маджонг использует сервер комнат. В каждой игре есть правила с примерами.

## Запуск

Нужен Node.js 22+.

```sh
npm run dev
npm test
npm run build
```

Локальный адрес: http://127.0.0.1:5173. Сборка в `dist/`.

## Онлайн-маджонг

Для проверки на одном компьютере откройте четыре отдельных вкладки и займите места по коду. Создатель стола запускает раздачу после входа всех четырёх. Если ссылка открывается в том же браузере как копия вкладки и показывает уже занятое вами место, откройте её в новой вкладке вручную или используйте отдельный профиль.

Для игры из интернета запустите `node scripts/serve.mjs` на Node.js 22+ за HTTPS-прокси. Можно указать `HOST=0.0.0.0` и нужный `PORT`. На GitHub Pages добавьте переменную Actions `MAHJONG_API_URL` с HTTPS-адресом сервера (без пути). На сервере задайте `TABLE_ORIGIN` с origin сайта Pages (например, `https://example.github.io`, без имени репозитория). Workflow передаст URL сборке. Без него на Pages остаётся доступен раздел правил. Сервер хранит комнаты в памяти одного процесса до перезапуска или 12 часов без ходов. Для игры в одной локальной сети можно запустить сервер на LAN-интерфейсе и зайти на него с устройств по адресу компьютера.

Пригласительный код нужен для входа, ключ конкретного места сохраняется отдельно в сессии вкладки. Сервер хранит руки и стену, а клиент получает свою руку, количество костей у других игроков и открытую информацию стола. Китайский и японский режимы рассчитаны на обучение и имеют упрощения, описанные в правилах игры.

## GitHub Pages

В настройках репозитория выберите **Pages → Source → GitHub Actions**. После отправки в `main` workflow `.github/workflows/pages.yml` проверит движок, соберёт сайт и опубликует Pages. Если основная ветка называется иначе, измените `branches` в workflow. Все пути относительные, маршруты используют hash: сайт работает и в подпапке репозитория. Публикация из текущей рабочей копии не выполнялась.

## Архитектура

- `src/app.js` — общая оболочка, каталог и маршрутизация.
- `src/data/games.js` — реестр игр и ленивые загрузчики модулей.
- `src/games/<id>/engine.js` — чистые функции игровой логики, без DOM.
- `src/games/<id>/view.js` — интерфейс и правила игры.
- `src/games/table-view.js` — общая оболочка для шахмат, шашек, нард и сёги с подсветкой ходов, отменой действий и сохранением.
- `src/style.css` — адаптивное оформление и общие компоненты.
- `tests/` — проверки игровых правил средствами Node.js.

Для новой игры добавьте каталог `src/games/<id>/`, экспортируйте `render(root)` из модуля интерфейса и зарегистрируйте игру в `games.js`. Карточки и поиск строятся из реестра. Движки не зависят от интерфейса и хранилища.

## Правила и ограничения

В го используются китайский подсчёт площади, коми 7,5, запрет самоубийства и позиционное суперко. Два паса завершают партию. Мёртвые группы автоматически не определяются: спорные позиции нужно доиграть через «Продолжить игру». Счёт берётся по текущей доске.

Правила сверены с материалами [British Go Association](https://www.britgo.org/intro/intro2.html) и [сравнением систем правил](https://www.britgo.org/rules/compare.html). Google Fonts необязательны: при отсутствии сети используется системный шрифт. Позиция хранится только в localStorage браузера.
